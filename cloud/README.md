# 예바 클라우드 자동 조사

GitHub Actions의 Linux 브라우저가 매일 한국시간 오전 9:30에 ChatGPT·Gemini를 비로그인으로 조사하고, 기존 Supabase의 본인 AI 기록에 저장합니다. 사용자 PC와 Codex 앱은 실행에 필요하지 않습니다. GitHub 예약은 혼잡 시 지연될 수 있습니다.

현재 저장소는 공개 저장소입니다. GitHub 정책상 저장소 활동이 60일간 없으면 예약이 자동 중지될 수 있으므로 장기 운영 시 Actions의 활성 상태를 확인해야 합니다. 재활성화는 저장소의 Actions 화면에서 가능합니다. 근거: https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule

## 실행

- 운영: `.github/workflows/radar-cloud-collect.yml` (`Radar cloud daily collection`). 예약 및 수동 실행을 지원합니다.
- 접근·질문 시험 워크플로는 수동 실행만 지원합니다. 운영 저장은 하지 않습니다.
- 2026-10-01 운영 시험: 실행 `36802941471`에서 미수집 2건을 채우고 서버의 오늘 완료 6/6건을 확인했습니다. 기존 성공 4건은 보존했습니다. 최초 예약 실행일은 2026-10-02입니다.

## 인증과 저장

Supabase의 `yeba-radar-cloud` Edge Function은 GitHub가 서명한 단기 OIDC 토큰을 검증합니다. 저장소 ID, 소유자 ID, main 브랜치, 정확한 운영 워크플로 경로, 실행 이벤트를 검사합니다. 관리자 키를 GitHub에 복사하지 않습니다. 이 함수만 레거시 JWT 검사를 끄고 자체 검증을 사용하며 익명·위조 토큰은 401로 거부합니다.

소유 계정은 서버에서 고정합니다. 사이트에 저장된 질문과 당일 ChatGPT·Gemini 결과만 읽고 저장하며 다른 업무 테이블은 사용하지 않습니다. 질문마다 저장하고, 같은 날짜·AI·질문의 성공 기록은 다시 전송하거나 덮어쓰지 않습니다. 현재 질문 수는 3개이며 실행 제한은 30분입니다.

## 수집과 분류

질문마다 빈 비로그인 브라우저 컨텍스트를 사용합니다. 접근 제한·로그인 요구·CAPTCHA를 우회하지 않습니다. 응답 생성 오류나 시간 초과는 실패로 저장합니다. 화면에 보이는 답변 원문을 유지하고 추천 치과의 독립된 제목·목록·비교표 첫 열을 자동 추출합니다. 지점 표기는 보존하고 다국어 지도 카드의 번역 표기만 정리합니다. 분류가 불확실하면 원문과 검토 사유를 실패 기록에 남기고 추천률에서 제외합니다. 자동 분류이므로 화면 구조 변화와 병원명이 섞인 문장은 원문 검토가 필요합니다.

## 운영 확인

Actions 요약과 `verified.json`에서 서버 재조회한 완료 건수를 확인합니다. 일부 미수집 또는 저장 오류가 있으면 실행을 실패로 표시합니다. GitHub 알림 수신은 계정의 Actions 알림 설정을 따릅니다. 별도 이메일·메신저 발송은 설정하지 않았습니다. 증거 파일은 3일 보관합니다. 접근 시험 성공은 실제 응답 수집 성공을 의미하지 않습니다.

예약 변경은 운영 워크플로에서 합니다. 페이지의 API 자동 실행 스위치와 시각은 클라우드 예약을 변경하지 않습니다. API 응답을 비로그인 웹 응답으로 대체하지 않습니다.
